# Japan Trip Planner — Plan

## Goal

Personal web app to view/edit Japan itinerary on phone during trip. Minimal mobile data use (eSIM). Read-only offline.

## Stack

- Next.js (App Router, TS) on Vercel
- Supabase Postgres (accessed server-side only)
- Tailwind CSS, dark theme only
- Hand-written service worker (`public/sw.js`, no build plugin) for PWA
- `idb-keyval` for IndexedDB cache (tiny)
- `jose` for session cookie signing
- No map embeds, no web fonts, no images, no UI kit → small bundle

## Data model (Supabase SQL migration)

```sql
create type location_type as enum ('area', 'place');

categories (
  id uuid pk default gen_random_uuid(),
  name text not null unique,
  emoji text,                      -- optional default emoji for new locations
  created_at, updated_at
)

locations (
  id uuid pk default gen_random_uuid(),
  type location_type not null,
  parent_id uuid null references locations on delete cascade, -- place → its area; area delete deletes its places
  category_id uuid null references categories on delete set null,
  name text not null,              -- name/title shown everywhere
  description text,
  emoji text not null default '📍',
  city text not null,
  lat double precision not null,
  lng double precision not null,
  created_at, updated_at,
  check (type = 'place' or parent_id is null)  -- areas have no parent
)
-- trigger: parent_id must point to a location with type = 'area'

days (
  id uuid pk,
  date date not null unique,
  title text,                      -- e.g. "Tokyo – Shibuya"
  note text,                       -- optional day-level note
  created_at, updated_at
)

create extension if not exists btree_gist;

stays (                            -- hotel booking over a date range, independent of days
  id uuid pk,
  location_id uuid not null references locations on delete cascade, -- picked from collection
  name text not null,
  airbnb_url text not null,        -- must be https://*.airbnb.* (opens Airbnb app via universal link)
  check_in date not null,
  check_out date not null,
  created_at, updated_at,
  check (check_out > check_in),
  exclude using gist (daterange(check_in, check_out, '[)') with &&) -- no overlapping stays
)
-- day D's hotel = stay where check_in <= D < check_out (night of D)
-- checkout day = stay where check_out = D

day_items (
  id uuid pk,
  day_id uuid references days on delete cascade,
  location_id uuid null references locations on delete cascade, -- null = note-only item
  time time null,                  -- null = untimed
  position int not null default 0, -- order for untimed items
  note text,                       -- reminders: transport, weather warnings, etc.
  created_at, updated_at,
  check (location_id is not null or note is not null)
)
```

- `updated_at` trigger on all tables
- `data_version` single-row counter bumped by trigger on any write → ETag
- RLS enabled, no policies → anon key useless; server uses service role key (never sent to browser)
- Cascades: delete area → its places → their day items; delete location → its day items + stays using it; delete day → its items; delete category → locations become uncategorized

## Location types

- **Area**: region/neighbourhood (e.g. Shibuya). Own lat/lng. Contains 0..n places.
- **Place**: specific spot. Optional `parent_id` → area.
- Both addable to a day. Area in day → shows all its places (expandable list).
- Every location row, stay (via its location), and area child has **📍 Maps button** → `https://www.google.com/maps/search/?api=1&query=<lat>,<lng>` (opens Google Maps app; no map data in our app).

## Delete confirmation (all deletes)

- Shared `ConfirmDeleteDialog`: shows what will be removed (e.g. "Also removes 4 places and 2 day items"), text input, Delete button enabled only when input === `delete me`.
- Used for: categories, locations, days, day items, stays.
- Server action also requires `confirm: "delete me"` param (guards accidental calls).

## Auth (14-day login)

- Single user. Password scrypt hash in env (`APP_PASSWORD_HASH`, format `salt:hash` hex; generated by `npm run hash-password`).
- `/login` → `POST /api/login` verifies → signed JWT cookie (`jose`, HS256, `SESSION_SECRET`): `httpOnly`, `secure`, `sameSite=lax`, `maxAge = 14 days`.
- `middleware.ts` verifies cookie on pages + API; invalid → redirect `/login`.
- No refresh calls → no extra data; cookie ~200 B. Small delay on failed login.
- Not Supabase Auth: large cookies (~3–4 KB per request) + refresh network calls.

## Pages (hash routes inside `/`)

- `/login` — password form
- `#/` — Days list: date, title, hotel name, item count; "+ New day"
- `#/day/<id>` — Day detail
  - Header: date, title, day note (optional)
  - Hotel card (derived from stays): tonight's stay (name, 📍 Maps, "Open in Airbnb", "Night 2 of 4"); on checkout day also "Check out: <name>"
  - **Timed** section (heading): items sorted by `time` asc
  - **Anytime** section (heading): untimed items, ordered by `position` (move up/down)
  - Item row: `HH:MM` + emoji + name + city + Maps button; note below, highlighted ⚠️
  - Note-only item: 📝 + note text (can be timed or untimed)
  - Area item: expand → all its places, each w/ Maps button
  - "+ Add" → sheet: **Location** (search/filter collection, optional time, optional note) or **Note** (text, optional time)
  - Edit item (time / note), delete item (confirm)
  - Edit day: title, note, delete day (confirm)
- `#/locations` — Collection
  - Filter: All | Areas | Places; by city & category (client-side)
  - Places show parent area name
  - Add / edit / delete (confirm)
- `#/location/<id>` — Location detail
  - Area: info, Maps button, places inside (tap → detail), "+ Add place to this area"
  - Place: info, Maps button, link to parent area
- `#/stays` — Hotels list sorted by check-in: name, dates, nights, 📍 Maps, Airbnb
  - Add / edit: pick location from collection (`LocationPicker`), name prefilled from location, Airbnb link (required), check-in + check-out dates
  - Overlap → form error; delete (confirm)
  - Reachable from Days page header
- `#/categories` — list, add / rename / change emoji / delete (confirm; shows count of affected locations)
  - Reachable from Locations page header (and category select "+ New category")
- Location form: type, parent area (places only), name, description, category (select), emoji, city, lat, lng
  - Paste Google Maps URL → parse lat/lng
  - New place in area: prefill city; picking category prefills emoji

## Data-efficiency strategy

1. **One sync endpoint**: `GET /api/data` returns categories + locations + stays + days + items as compact JSON. Whole trip likely < 30 KB, Brotli → ~5 KB.
2. **ETag / 304**: ETag = `data_version`; unchanged → `304` (~200 B).
3. **Local cache**: client store (`useSyncExternalStore`) hydrated from IndexedDB instantly; background revalidate on app open / focus, throttled ≥ 5 min; no polling.
4. **Mutations**: JSON route handlers (`/api/<resource>`); local store updated from response (changed row + new version); deletes → client prunes cascaded relations locally.
5. **Static app shell**: single page reads from local store (no per-navigation server fetch); service worker caches HTML (stale-while-revalidate) + hashed assets (cache-first) → repeat visits load ~0 B assets.
6. **Offline**: read-only from IndexedDB; edit buttons disabled + "offline" badge.
7. **Bundle discipline**: system fonts, native emoji, no icon/date/map libs, no Supabase client in browser, `<Link prefetch={false}>`.
8. Headers: Vercel Brotli; `/api/data` → `Cache-Control: private, no-cache`; hashed assets immutable.

## Logging

- Server logs structured JSON only: `@timestamp`, `level`, constant `message`, `service`, `env`, `request_id`, `logger`; `snake_case` fields.
- Never log password, session cookie/JWT, service role key.
- Errors logged once at action/route boundary with error object. `INFO` prod, `DEBUG` dev only.

## Mobile UX

- Built for phone first (iPhone/Android, 360–430 px wide); desktop = same column centered (`max-w-md`)
- Single-page app: one route `/` w/ hash routing (`#/day/<id>`) → navigation costs 0 bytes; browser back works
- Fixed bottom tab bar: **Days | Locations | Stays**; safe-area insets (`viewport-fit=cover`, `env(safe-area-inset-*)`)
- Sticky top header: back arrow, title, one primary action (+)
- Tap targets ≥ 44 px; body text ≥ 16 px (stops iOS zoom on input focus); high contrast (WCAG AA)
- Forms + pickers open as bottom sheets (thumb reach); primary button sticky at sheet bottom
- Native inputs: `type=date`, `type=time`, `inputmode=decimal` for lat/lng
- Days list opens scrolled to **today**; "Today" chip jumps to current day
- Big one-tap 📍 Maps + Airbnb buttons; long text wraps, never horizontal scroll
- Anytime reorder via ↑ / ↓ buttons (no drag — reliable on touch)
- Toasts for saved / error; empty states with clear CTA; offline badge explains why edit buttons are disabled

## Design

- Dark: bg `zinc-950`, cards `zinc-900`, text `zinc-100`, single accent (red)
- Area vs place chip; note callout amber; delete buttons red
- Mobile-first, large tap targets, bottom nav: Days | Locations
- PWA manifest → "Add to Home Screen", standalone, dark theme-color
